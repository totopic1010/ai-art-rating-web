# 09｜14日間の学習ロードマップ：分からない状態から、自分で改良するまで

目的は「コードを眺めて分かった気になる」ではなく、**自分で小さく変更して、なぜ動いたか説明できること**です。

毎日30～60分の例です。理解に時間がかかっても大丈夫。無理に次へ進むより、前日の復習を優先します。

## もっと簡単に始める「最初の3つの演習」

### 演習A：文章を変える
1. `public/index.html` で「この作品をどう感じますか。」を探す。
2. 「あなたはこの絵をどう評価しますか。」に変更する。
3. 保存してローカル画面を再読み込み。
4. 何を変えたら、どこが変わったか書く。

**学び**：HTMLは画面に表示する情報を持つ。

### 演習B：画像サイズを変える
1. `public/styles.css` を開く。
2. `.art-frame img` の `height` の値を少し変更。
3. ブラウザを更新し、画像の大きさを比べる。

**学び**：CSSが見た目を決める。

### 演習C：採点ルールを読む
1. `app.py` の `class Rating` を探す。
2. `score: int = Field(ge=0, le=100)` を読む。
3. 「100点はOK、101点はNG」と説明する。
4. `supabase/schema.sql` にも `between 0 and 100` があることを見つける。

**学び**：同じ点数ルールをPythonとデータベースの両方で守る。

## 3分で説明するための発表台本
> AI Art Ratingは、AIで作られた画像を人がどう評価するかを記録するWebアプリです。画面はHTMLとCSSで作り、JavaScriptが操作を担当します。ユーザーの点数はPythonのFastAPIへ送られ、入力に問題がないかチェックしてからSupabaseに保存されます。データをSQLで集計することで、作品ごとの評価傾向を見られます。GitHubでコードを管理し、Vercelで公開しています。ただし、正式な研究実験として使うには、参加者の認証や同意、実験条件の統制が今後必要です。

## つまずいたときの3つの質問
- **どこ？**：どのファイルのどの関数？
- **何を受け取る？**：作品ID・点数・JSONなど何が入る？
- **何を返す？**：画面変更・DB保存・数値など何が出る？

「この関数は何を受け取り、何をするか」を言葉にできれば、かなり理解が進んでいます。
