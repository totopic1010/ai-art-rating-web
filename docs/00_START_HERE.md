# 00｜はじめての人へ：AI Art Ratingを理解する入口

対象：プログラミング未経験者。専門用語は初出で説明します。2026年11月23日時点の公開ソースに基づく説明です。

## そもそも何を作った？
「AIが作った絵を人間が見ると、何を美しいと感じるのか」を調べるための **ブラウザで動く評価アプリ** です。
作品を50枚眺め、0～100点で採点し、理由を選び、情報提示後に再評価したり、2枚を比較したりできます。「結果」画面では集計結果を見られます。
ここでいう AI は **画像の制作元**。このアプリ自体が画像を自動生成するわけではありません。

- アプリ： https://ai-art-rating-web.vercel.app/
- ソースコード： https://github.com/totopic1010/ai-art-rating-web
- この教科書の目次： ../README.md

## レストランに例えると
- **HTML**：お店の間取り。「ここに画像」「ここに採点ボタン」という場所を用意。
- **CSS**：内装デザイン。白背景、文字の色、余白、作品画像のサイズを指定。
- **JavaScript**：店員。ボタンを押したら画像を切り替え、点数を送信。
- **Python / FastAPI**：厨房・受付。注文を受け、値が正しいか確認してデータを保存。
- **データベース**：帳簿。誰がどの絵に何点を付けたか記録。
- **Supabase**：インターネット上のデータベース提供サービス。
- **Vercel**：プログラムを置いてインターネットで動かす場所。
- **GitHub**：設計図やプログラムの「変更履歴を残せる保管庫」。
- **API**：店員と厨房の受け渡し窓口。決まった形式でデータをやり取りする。

### 1件の採点で実際に起きること
1. ブラウザに1枚の絵が出る。
2. 鑑賞者がスライダーを72にして、理由に「構図」を選ぶ。
3. JavaScriptが「作品ID・72点・理由・判断時間・匿名識別子」をまとめる。
4. Pythonの `POST /api/ratings` にそのデータが届く。
5. Pythonが点数の範囲、作品ID、理由をチェックする。
6. 公開サイトではPythonが秘密鍵を使ってSupabaseへ保存する。
7. 「結果」を開くと `GET /api/stats` で集計値を取得して画面に描く。

**重要：秘密鍵は「ブラウザに渡さず、サーバー側だけで使う」必要があります。**

## 最初の5分：何を見ればよい？
1. 公開アプリで1枚を見て、左右の矢印を押す。
2. 点数スライダーを動かす。画面の数字が変わる。
3. 「評価理由を追加」を開く。
4. 「評価を確定」→ 制作情報を見るダイアログ →「そのまま確定」または「再評価を保存」を選ぶ。
5. 「比較」「結果」も見てみる。

採点を確定するとデータベースに保存されます。試すだけなら、公開中の研究用データと混在する可能性を考慮してください。

## 言葉が分からなければ
- **変数**：データに付ける名前。例：`score = 72`。
- **関数**：処理をひとまとまりにして名前を付けたもの。例：`renderArtwork()` は絵を表示する処理。
- **条件分岐**：`if`。「もし採点済みならボタンを押せなくする」。
- **配列／リスト**：複数のデータの並び。50作品の一覧が一例。
- **オブジェクト／辞書**：「項目名：値」のセット。例：作品IDと点数。
- **HTTP**：ブラウザとサーバーが通信する仕組み。`GET` は取得、`POST` は送信。
- **JSON**：データを「キー：値」で表す形式。APIのデータ交換に使用。
- **SQL**：データベースへ保存・検索・集計を頼む言語。
- **デプロイ**：自分のパソコンで動くプログラムを公開用サーバーへ配置すること。
- **リポジトリ**：GitHubで管理する一つのプロジェクト。
- **コミット**：変更を履歴として記録する操作。
