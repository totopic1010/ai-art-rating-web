# 01｜要件定義書：何を作ることにしたのか

最終確認：2026年11月23日。現行リポジトリの実装を基準に **実装済み / 制約あり / 未実装** を分けました。

## 1. 背景と目的
AI画像に対する人間の美的判断を、作品別・ジャンル別・評価理由別に観察するための試作アプリ。
大学の美学研究へ発展させられるが、**現在の版は厳密な研究実験として検証済みではない**。

### 想定する利用者
- 鑑賞者：画像を見る、採点する、比較する、自分の評価を確認する。
- 開発者：画像・プログラム・データベースを管理し、集計傾向を観察する。
- 研究者：将来的に適切な同意と条件統制のもとで実験に利用する。

## 2. 必須の体験（ユーザーストーリー）
> 私は鑑賞者として、1枚ずつAIアートを見て0～100点で評価し、50枚全体で自分の好みや他人との違いを知りたい。

手描きUIの意図：
- 白背景＋黒文字＋広い余白。
- 中央に大きく作品を表示。
- 上部に `01 / 50` と左右の移動ボタン。
- 左側に進行状況の目盛り。
- 下部に `0 ～ 100` のスライダー。
- 「鑑賞」「比較」「結果」を移動できる。

## 4. 非機能要件（品質）
- **使いやすさ**：最初に50点が表示され、1画面で鑑賞と採点ができる。
- **デザイン**：ミニマルな白黒の意匠。画像が主役。
- **Web対応**：Safariなどの現代的ブラウザを想定。スマートフォン向けCSSも存在するが実機評価は別途必要。
- **入力安全性**：Python／Pydanticで点数・長さ・UUIDを検証。
- **鍵の秘匿**：Supabaseの秘密鍵はVercel環境変数。JavaScriptに埋め込まない。
- **保存**：公開環境はSupabase、ローカルは既定でSQLite。
- **テスト**：`tests/test_app.py` にAPIの正常系・重複・不正値テスト。
- **可用性**：外部プラットフォームの無料枠、制限、サービス障害に依存する。
- **バックアップ**：自動バックアップの構成や研究データ保全計画は未整備。

## 5. 入力・出力
鑑賞者が送る評価には次が含まれます。
- `artwork_id`：作品ID（例 `ART-001`）
- `participant_id`：匿名識別子（UUID）
- `score`：最初の点数（0～100）
- `reason`：評価理由（任意）
- `duration_seconds`：経過秒数
- `revised_score`：再評価した点数（任意）
- `info_shown`：制作情報を提示したか

出力例：
- 50作品のタイトル・ジャンル・画像パス
- 集計された全回答の件数・平均点・理由の分布
- 自分のブラウザに残る回答から作るCSV

## 6. 現状の重要な制約
1. **鑑賞者が意図的に複数回参加することを防げない**。ブラウザのデータ削除や別端末でIDは変えられる。
2. **情報を提示したことの因果効果は測定できない**。任意の再評価・提示順固定・対照群なし。
3. **ジャンル名は開発側が付けた便宜的な分類**で、正解を保証しない。
4. **50画像は1つのAI生成コンタクトシートから切り出したテスト素材**。独立した50回の生成結果ではない。
5. **実験用の同意画面や倫理審査に必要な説明はまだない**。
6. 全体平均には本人の回答も含まれるため、`他人だけの平均` ではない。
